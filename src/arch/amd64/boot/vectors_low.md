# Module: vectors_low (amd64 boot)

## Purpose

Auto-generated ISR stubs for exception vectors 0-127: `sys_amd64_vectors_start`
and the first half of the 256-entry stub table, one `asm_exception_N` label
per vector. Paired with `vectors_high.S` (vectors 128-255 plus the shared
`common_handler` they all jump to) -- split in two because the full table is
~1800 lines, over this project's 1200-line boundary-check limit for a single
`.S` file.

## Responsibilities

- Push the CPU-supplied error code (or a dummy 0, for vectors that have
  none) followed by the vector number, then jump to `common_handler` in
  `vectors_high.S`.
- Nothing else: register save, the call into
  `sys_amd64_exception_handler`, and the halt-on-return fallback all live
  in `common_handler`, not here.

## Invariants

- Generated by `tools/kernel/gen_vectors.py`; do not hand-edit. Regenerate
  with `python3 tools/kernel/gen_vectors.py <low> <high> <table>` if the
  stub body or the low/high split point ever needs to change.
- No exceptions, RTTI, implicit allocation, or hosted C++ runtime dependency.

## Verification

`sys::arch::exception::initialize_idt()` now reads
`sys_amd64_vector_table` (built by the same generator, from
`vectors_table.S`) to install a real IDT pointing at these vectors -- these
stubs are no longer dead code eliminated by `--gc-sections`; confirmed via
`nm` on the linked ELF. Not verified by execution: QEMU's multiboot loader
only accepts a 32-bit kernel (see `tools/run/run.sh`), so this architecture
has not booted in this environment, and no interrupt has ever actually
reached one of these stubs.
