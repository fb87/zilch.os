# Module: vectors_high (amd64 boot)

## Purpose

Auto-generated ISR stubs for exception vectors 128-255, plus
`common_handler`: the trap entry every stub in both this file and
`vectors_low.S` jumps to, and `sys_amd64_vectors_end`, closing the range
`sys::arch::exception::fault_address()` and friends reference via
`sys_amd64_vectors_start`/`_end`.

## Responsibilities

- The vector 128-255 stub table, identical shape to `vectors_low.S`'s.
- `common_handler`: saves the general-purpose registers in `frame_t`'s
  field order, calls `sys_amd64_exception_handler` with `%rsp` pointing at
  the assembled frame, and halts if that call ever returns (it should not).
- Exports `common_handler` as `.global` specifically so `vectors_low.S`'s
  `jmp common_handler` -- a reference across two separate translation
  units -- resolves at link time.

## Invariants

- Generated by `tools/kernel/gen_vectors.py`; do not hand-edit.
- No exceptions, RTTI, implicit allocation, or hosted C++ runtime dependency.
- The register push order in `common_handler` must match
  `sys::arch::exception::frame_t`'s field layout exactly; that struct's own
  `static_assert`s on `sizeof`/offsets are the check that would catch drift
  here, since nothing else at compile time connects assembly push order to
  a C++ struct layout.

## Verification

See `vectors_low.md` -- same status: reachable via a real IDT now, but not
yet verified by execution in this environment.
