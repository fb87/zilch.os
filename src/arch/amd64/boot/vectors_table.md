# Module: vectors_table (amd64 boot)

## Purpose

`sys_amd64_vector_table`: a 256-entry `.quad` array of the address of each
`asm_exception_N` stub, read once by `sys::arch::exception::initialize_idt()`
to populate the real IDT.

## Responsibilities

- Nothing beyond the address table itself. A separate generated file rather
  than folded into `vectors_low.S`/`vectors_high.S`: it references all 256
  stub labels regardless of which of those two files defines them, and
  keeping it apart means neither stub file needs to know the other exists.

## Invariants

- Generated by `tools/kernel/gen_vectors.py`; do not hand-edit.
- No exceptions, RTTI, implicit allocation, or hosted C++ runtime dependency.

## Verification

This is the table whose read from C++ (`initialize_idt()`) is what keeps
the entire vector-stub chain from being discarded by `--gc-sections` --
before that read existed, `sys_amd64_vectors_start`/`asm_exception_N`/
`common_handler` were unreferenced by any relocation the linker could see,
and none of them survived into the linked image. Confirmed present via
`nm` on the linked ELF as of `sys::arch::exception`'s IDT construction.
