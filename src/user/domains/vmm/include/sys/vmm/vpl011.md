# Module: vpl011 (vmm)

## Purpose

Virtual ARM PL011 UART device *model*: register state and the layout
needed to decode a trapped guest access. See
`src/user/domains/vmm/README.md` for why this is split from
`src/user/servers/domain`, which holds everything that actually forwards
characters, injects the guest IRQ, and advances the guest PC -- authority
this model deliberately does not have.

## Responsibilities

- Model only the registers a real guest PL011 driver touches: DR, FR
  (RXFE/TXFF), IMSC (RXIM), CR. Everything else in the 4 KiB IPA window is
  a safe write-and-discard / read-returns-zero, left to the server.
- `owns(ipa)`/`is_write(qualification)`/`source_register(qualification)`:
  pure decode helpers for a trapped stage-2 abort, so the server's dispatch
  loop does not hand-roll bit arithmetic at each call site.
- Buffer guest TX bytes (`tx_buffer`) rather than forwarding synchronously
  per register write -- one blocking IPC round trip per guest write
  previously dominated observed serial latency.

## Invariants

- Pure data and register-decode logic: no capability, no syscall.
- No exceptions, RTTI, implicit allocation, or hosted C++ runtime dependency.
- `qualification_write_bit`/`qualification_srt_shift`/`qualification_srt_mask`
  are the one genuinely arm64-specific piece here, matching
  `src/arch/arm64/include/sys/arch/hypervisor.hh`'s `mmio_qualification()`
  bit layout exactly. A VMX host would decode an exit qualification with an
  entirely different layout, and an x86 guest would expect a 16550A, not a
  PL011, in the first place.

## Verification

Exercised by `src/user/servers/domain/main.cc`'s guest MMIO-fault dispatch
whenever a guest touches this IPA window; end-to-end proof is
`tools/verification/smoke.sh`'s guest profile, which boots
`src/user/guests/vpl011-arm64` and asserts its output reaches the real UART.
